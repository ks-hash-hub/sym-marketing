01 — Overview
What we're building & why.
The problem, the goal, and the value it creates for the team.
⚠️
The Problem
Reps are pitching blind
Marketing reps have no unified view of a release's playlist potential. Insights are scattered across Airtable, Chartmetric, and email — there's no single score or signal that tells them how strong a pitch is before they send it.
🎯
The Goal
More playlists pitched. More playlists landed.
Give reps a scored, data-backed view of every priority release so they know which releases to prioritize, which pitches are strong, and what's missing before they send. Stronger pitches = more editorial placements = more value for Symphonic artists.
📈
The Value
Symphonic's marketing arm gets more powerful
A shared scoring model builds institutional knowledge. Reps know which signals matter. Leaders can see performance across the whole roster. Over time, the data gets better and so do the pitches.
North Star
"More editorial playlists to pitch to. More editorial playlists to land on." — The goal is to make Symphonic's marketing team measurably more effective at getting releases in front of the right curators.

02 — Users
Who this is for.
Internal tool first. The primary users are Symphonic marketing reps and their leads.
🎧
Primary User
Marketing Rep
Works the release schedule daily in Airtable. Pitches editorial playlists, writes driver submissions, tracks pickups. Needs a fast read on pitch readiness without leaving their workflow.
Key pain points
  • No single score to prioritize releases
  • No reminder when driver submission is missing
  • Can't see pickup history without switching tools
📊
Secondary User
Marketing Lead / Director
Oversees the roster and team performance. Wants visibility into which releases are strongest, where the team's attention should go, and how the scoring model is performing over time.
Key needs
  • Sort/filter full roster by score
  • See which releases have gaps
  • Input on how the score is weighted
Internal First
This tool is for the Symphonic team only. Access is gated to @symdistro.com Google accounts via Cloud Run's Identity-Aware Proxy. Client-facing features are out of scope for v1.
User Stories
Marketing Rep
As a rep, I want to see a score for every priority release so I can quickly decide which ones to pitch first without having to look up data in multiple tools.
Marketing Rep
As a rep, I want to be warned when a driver submission is missing so I don't pitch a release that isn't ready and lose credibility with curators.
Marketing Rep
As a rep, I want to see playlist targets ranked by match score so I know which curators to pitch without spending an hour on research.
Marketing Rep
As a rep, I want to view the full profile page from within Airtable so I can get the complete picture on any release in one click without leaving my workflow.
Marketing Lead
As a lead, I want to sort and filter the release schedule by SYM Score in Airtable so I can see the strongest pitches at the top and allocate the team's time accordingly.
Marketing Lead
As a lead, I want to have input on how the score is calculated so that the weights reflect what we know actually drives editorial placements.

04 — SYM Score
The scorecard we build together.
The SYM Score is a 0–100 composite score across 5 pillars. The weights below are a starting point — they get validated against real releases with the team before being locked in.
Important
The score is guidance, not a gate. A low score doesn't block a pitch — it surfaces where the gaps are. The rep always makes the final call. The score is designed to start conversations, not end them.

PillarWhat it measuresData sourceWeight
Pickups Editorial playlist placements on past releases. Artists with a track record of getting picked up are stronger pitches. Airtable Pickups table 25 pts
Audience Spotify monthly listeners and follower count. Proxy for how established the artist is in front of editorial curators. Chartmetric / Spotify API 20 pts
Social Social following and growth rate across platforms. Signals artist momentum and fanbase activity. Chartmetric 20 pts
Drive Driver submission completeness. No submission = incomplete pitch. Rewards reps who have done the prep work. Airtable Driver Submissions 20 pts
Consistency Release cadence and label activity over time. Labels that release consistently tend to have better curator relationships. Airtable Release Schedule 15 pts

Validation Process
Before the score formula is locked: run it against a sample of 20–30 real past releases, review the outputs with 2–3 reps, and adjust weights until the scores reflect what the team knows to be true. The formula lives in the app — changes take effect on the next nightly sync.

06 — Out of Scope
What this is not.
v1 is intentionally focused. These items are explicitly out of scope to keep the build lean and shippable.
ItemWhy it's out of scopeFuture?
Client-facing access Tool is internal only for v1. Sharing with artists or labels introduces privacy and data accuracy concerns that need separate planning. Later phase
Automated pitch sending The tool informs pitches, it doesn't send them. Keeping humans in the loop is intentional for v1. Later phase
Audio analysis / AI tagging Interesting future capability (Google Vertex AI is available via Cloud Run) but not needed to deliver core value in v1. Later phase
Label / artist login portal No external auth system in v1. IAP handles Symphonic team auth. External users are out of scope. Later phase
Real-time data updates Nightly sync is sufficient for v1. Real-time would add cost and complexity without meaningful benefit for a daily workflow tool. Later phase
Mobile app Desktop Airtable workflow is the primary context. Mobile is not a v1 requirement. Later phase
Open Questions

Profile Page
Which sections and signals should appear on the full profile page? The foundation is built — the layout needs to be finalized with the marketing team. Needs team input before Phase 1 ships.
Data Access
Does the Chartmetric API key in 1Password have the right scopes for playlist history and social stats? Needs technical confirmation before Phase 2 work starts.
Domain
Who manages the Symphonic DNS and can set up the labs.symphonic.com subdomain pointing to Cloud Run? Needs one-time coordination with whoever owns the domain.
